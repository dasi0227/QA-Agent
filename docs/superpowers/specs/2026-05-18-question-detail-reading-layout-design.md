# 题目表右侧主区域阅读化布局设计

## 1. 目标

将当前题目详情右侧主区域从“表单编辑感”重构为“深读型内容页”，核心目标如下：

- 优先服务阅读，不让用户产生“正在填写或编辑表单”的错觉
- 提升信息密度，但避免重复卡片堆叠
- 强化阅读顺序：题目 -> 标准回答 -> 知识点分析 / 题目信息 -> 证据原文
- 将模块、难度、标签等内容降级为元信息，而不是主叙事内容
- 为后续“知识点分析折叠展开”“证据原文替代 UUID”“固定高度内部滚动”预留稳定结构

## 2. 已确认的设计结论

### 2.1 页面阅读顺序

右侧主区域按以下顺序排列：

1. 题目标题
2. 标准回答
3. 合并卡片：左侧知识点分析，右侧题目信息
4. 证据原文

说明：
- 题目正文不重复展示两次
- 标准回答紧跟题目，作为最强内容段落
- 知识点分析与题目信息不再各自独立成卡，而是合并进同一个内容容器

### 2.2 合并卡片结构

采用“一张完整卡片 + 左宽右窄双列 + 柔和竖向分割线”的结构。

结构规则：
- 整个区域是一个完整卡片，不拆成两个独立卡片
- 左列承担文本说明内容，宽度更大
- 右列承担元信息展示，宽度更窄
- 左右两列之间使用柔和分割线，不使用强烈边框、不使用导向装饰条
- 左列标题与右列标题必须顶线水平对齐

最终命名：
- 左列标题：`知识点分析`
- 右列标题：`题目信息`

### 2.3 左列：知识点分析

左列是该合并卡片的主内容区。

交互与表现规则：
- 默认折叠，仅展示压缩预览
- 展开按钮与标题同一行，位于标题右侧
- 展开后内容在当前块内部滚动，不拉长整页布局
- 左列内容允许较长文本，因此需要固定区域高度和独立滚动能力

设计意图：
- 保留知识点分析的内容价值
- 让其成为“补充理解”的正文附页，而不是主答案的竞争者

### 2.4 右列：题目信息

右列是轻量元信息区，用于承载：
- 模块
- 难度
- 标签

表现规则：
- 必须有标题 `题目信息`
- 保持为完整信息块，不拆成多个白色小卡片
- 不展示“x 段证据”之类弱价值统计
- 标签继续使用轻量 pill/tag 形式
- 模块与难度采用分组文字展示，弱于正文，强于辅助注释

设计意图：
- 让元信息存在但不抢阅读主线
- 避免再次回到“多个卡片组件拼接”的低级感

## 3. 视觉原则

### 3.1 去表单化

以下元素应在正式实现中被移除或替换：
- 多行文本框样式
- 表单输入框边界感
- 重复的字段标签与字段值结构
- 看起来像可编辑控件的容器造型

替代方向：
- 使用排版分区代替表单控件
- 使用固定高度内容面板代替自适应文本框
- 使用标题、分隔、滚动区域表达层次，而不是输入框形态

### 3.2 卡片克制

本页面不能依赖重复卡片制造层次。

明确规则：
- 主区域本身可以是一个整体容器
- 合并区内部不能再拆成两个独立重卡片
- 元信息区不得拆成多个小白底统计块
- 层次主要通过：排版、留白、分割线、文字权重、背景明度差来建立

### 3.3 信息层级

信息优先级从高到低为：

1. 题目标题
2. 标准回答
3. 知识点分析
4. 题目信息
5. 证据原文

说明：
- 证据原文不是主叙事，而是支撑材料
- 模块、难度、标签是元信息，不应在视觉上压过知识点分析

## 4. 内容组件设计

### 4.1 题目标题

要求：
- 放在最上方
- 作为主标题展示
- 不在正文区域重复出现一次简化版问题文本

### 4.2 标准回答

要求：
- 紧跟标题下方
- 作为第一主要内容块
- 采用阅读型段落展示，而不是可编辑文本域
- 支持固定高度与内部滚动，但默认应优先保证首屏可读性

### 4.3 知识点分析

要求：
- 位于合并卡片左侧
- 默认折叠
- 标题行为固定为 `知识点分析`
- 内容区未来应支持较长文本
- 展开态和折叠态都不能破坏右列对齐关系

### 4.4 题目信息

要求：
- 位于合并卡片右侧
- 标题行为固定为 `题目信息`
- 内容包括模块、难度、标签
- 右列宽度固定或半固定，不随正文长度漂移
- 标签数量较多时允许换行，但整体区域仍需保持规整

### 4.5 证据原文

要求：
- 位于合并卡片之后
- 用阅读型引用或证据片段的形式展示
- 当前先以结构占位，后续数据内容会从 UUID 过渡到用户资料的确切文本

## 5. 布局与约束

### 5.1 宽度比例

已确认原则：
- 左侧文本区宽
- 右侧元信息区窄

建议实现约束：
- 左右比例保持在约 `1fr / 220px` 或相近范围
- 优先保证左列文本阅读舒展，不为右列让出过多宽度

### 5.2 对齐规则

强约束：
- `知识点分析` 与 `题目信息` 两个标题必须水平顶线对齐
- 左右列顶部内边距必须统一
- 展开按钮存在时，不得破坏标题行高度平衡

### 5.3 滚动策略

后续实现中需要统一采用“固定高度 + 内部滚动”的思路，适用于：
- 标准回答
- 知识点分析
- 证据原文（若内容较长）

原则：
- 避免页面整体高度被长文本无限拉长
- 保持版面稳定和首屏节奏

## 6. 不做的内容

本轮设计明确不包含以下内容：
- 不处理真实后端证据文本映射
- 不处理新增题目相关后端能力
- 不处理整页完整视觉实现
- 不处理移动端细节稿
- 不在本轮确定所有颜色、字体、动效细节

本轮只确定右侧主区域的信息结构与阅读布局。

## 7. 实施建议

如果后续进入实现阶段，建议按以下顺序落地：

1. 先替换当前表单型结构为阅读型 DOM 结构
2. 再处理标准回答、知识点分析、证据原文的固定高度与内部滚动
3. 再补知识点分析折叠/展开交互
4. 最后微调视觉细节，包括分割线强度、标题权重、标签样式

## 8. 验收标准

实现完成后，应满足以下判断标准：

- 用户第一眼认为这是“阅读页”，而不是“编辑表单”
- 题目不重复展示两次
- 标准回答位于题目之后，阅读顺序清晰
- 知识点分析与题目信息在同一张卡片中展示
- 左宽右窄成立
- 两个标题顶线水平对齐
- 右侧元信息不再拆成多个小白块
- 长文本不把整页无限拉长
